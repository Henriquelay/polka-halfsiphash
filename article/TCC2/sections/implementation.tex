\section{Implementing and Testing a Probing-Based Path Verification}


Assumptions:
\begin{inlinelist}
    \item Each node is assumed to be secure, that is, no node will alter the packet in any way that is not expected. This is a common assumption in SDN networks, where a trusted party is the only entity that can alter the network state;
    \item  Every link is assumed to be perfect, that is, no packet loss, no packet corruption, and no packet duplication;
    \item  Protocol boundary is IPv4. This means that \polka is only used inside this network, and only IPv4 is used outside;
    \item All paths are assumed to be valid and all information correct unless stated otherwise;
    \item Hash collisions will not happen.
\end{inlinelist}

\subsubsection{Parsing}
\anotacao{FIGURA desses subsub, ilustrando esse "pipeline", explicar em tópicos}

Parsing is done in edge nodes as follows:
\begin{itemize}
    \item If an IPv4 protocol \texttt{ethertype} field is detected (\texttt{0x0800}), it must be a packet from outside the network, it must be wrapped and routed by the same edge node that parsed it. Let call this process be called \textit{encapsulation};
    \item If a PolKA protocol \texttt{ethertype} field is detected (\texttt{0x1234}), it must be a packet from inside the network, since the protocol boundary is IPv4, the original IPv4 packet must be unwrapped. Let this process be called \textit{decapsulation}.
\end{itemize}

On core nodes, the packet is only parsed as PolKA packets, but it can be either a regular PolKA packet version or a probe packet version. If a probe packet version is detected, the probe packet header is parsed as well, otherwise the packet is treated a regular PolKA packet and no probing is done.

The implementation for parsing on edge nodes can be found in \ref{app:edge_parser}, and for core nodes in \ref{app:core_parser}.

\subsubsection{Encapsulation} \label{sec:encapsulation}

PolKA headers consists of the route polynomial (\texttt{routeid}), along with \texttt{version}, \texttt{ttl} and \texttt{proto} (stores the original \texttt{ethertype}). \texttt{route\_id} calculation is out of the scope of this paper.

A new header is added for probe packets, containing a $32$ bit \texttt{key} and $32$ bit \texttt{l\_hash}.

During encapsulation of a probe packet, a random number is generated, and is used as \texttt{key}, for reproducibility and a seed for our composition. Edge nodes does not execute checksum functions and only repeats the key into the checksum field \texttt{l\_hash}, so \texttt{node\_id} for encapsulation is not required.

After encapsulation, the packet is sent to the next hop.

The implementation for encapsulation and related headers can be found in \ref{app:encapsulation}.

\subsubsection{Composition}
Every core node does checksum trying to congregate the previous \texttt{l\_hash}, the calculated next hop port, and its own \texttt{node\_id} into the $32$ bit field. Currently, it is implemented as such:

$$ \texttt{l\_hash} \leftarrow \text{CRC32} (\text{exit port} \oplus \texttt{l\_hash} \oplus \texttt{node\_id}) $$

The CRC32 checksum function used currently is the one available by BMv2 standard library, and is experimentally found to be ISO HDLC\footnote{\url{reveng.sourceforge.io/crc-catalogue/all.htm\#crc.cat.crc-32-iso-hdlc}}.

\subsubsection{Decapsulation}

At the egress node, Polka headers are dropped, and the packet becomes an identical packet to what the ingress node received. The probe packet header is also dropped. The packet is then sent to the host. No checksum is calculated, so \texttt{node\_id} is not required. Thus, together with \ref{sec:encapsulation}, the \texttt{node\_id} is not used for validation on edge nodes.

The implementation for decapsulation can be found in \ref{app:decapsulation}.

The algorithm was verified externally through another program simulating all the composition steps, with source available\footnote{\url{github.com/Henriquelay/polka_probe_checker}}, making use of the `crc` library crate\footnote{\url{github.com/mrhooray/crc-rs}}, and checked with gathered data.

The implementation for a node doing an individual checksum calculation step can be found in \ref{app:calculation}.
